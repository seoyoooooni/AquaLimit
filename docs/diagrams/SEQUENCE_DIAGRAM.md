# AquaLimit 시퀀스 다이어그램

원본: [aqualimit-sequence.drawio](diagrams/aqualimit-sequence.drawio) (draw.io에서 열어 수정)

목표 서비스 구조의 호출 순서다. 현재 데모는 Streamlit 단일 앱이며, 아래 역할 분리는 다음 개발 단계에서 구현한다.

## 참여자

| 참여자 | 역할 |
|---|---|
| 사용자(운영 담당자) | 지역·우물·자료 등록, 계획 조건 입력, 계산 시작 |
| 승인자(운영 책임자) | 계산된 계획 검토, 승인 또는 반려 |
| 프론트엔드 | 입력 화면, 1차 입력 검사, 결과·보고서 표시 |
| 백엔드 API | 인증, 입력 재검증, 작업 등록, 승인 처리 |
| 작업 큐·워커 | 오래 걸리는 계산과 주기 작업을 비동기로 실행 |
| 모델 엔진 | InSAR 변환, 역산, 대리모델, 강건 최적화, 물리모델 재검증 |
| DB·저장소 | 사용자, 지역, 원본 자료, 모델 버전, 실행 결과, 승인 이력 |
| 외부 데이터 | Sentinel-1·InSAR 변위, 관측정 수위 |

## 페이지

| 페이지 | 흐름 |
|---|---|
| 00 전체 서비스 흐름 | 접속 → 위성 관측 갱신 → 계획 계산 → 승인·보고서 요약 |
| 01 접속 · 지역 · 자료 등록 | 로그인, 대시보드, 우물·관리지점·관측 자료 등록과 검증 실패 처리 |
| 02 위성 관측 갱신 · 모델 재보정 | 주기 실행으로 새 관측 수집, 앙상블 갱신, 기존 승인 계획 재평가 경고 |
| 03 취수 계획 계산 | 입력 확인 후 계산 시작, 워커에서 대리모델·강건 최적화, 해 없음이면 실행 불가 저장 |
| 04 계획 승인 · 보고서 | 승인 시 모델 버전 최신 여부 확인, 확정·이력 저장, 보고서 생성 |

## 설계 원칙

- 백엔드는 프론트 검사 결과를 그대로 믿지 않고 다시 검증한다.
- 계산은 요청 즉시 실행 ID를 돌려주고 워커에서 비동기로 수행한다. 프론트는 상태를 주기적으로 조회한다.
- 모든 결과는 사용한 모델 버전과 입력 스냅샷에 묶여 저장된다.
- 새 위성 관측으로 모델이 갱신되면 이전 모델로 계산한 계획은 승인 전에 재계산을 요구한다.
- 조건을 만족하는 해가 없으면 계획을 만들지 않고 실행 불가와 원인 제약을 저장한다.
