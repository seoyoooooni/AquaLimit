# AquaLimit 기술 설계

## 1. 전체 흐름

`InSAR 변형 시계열 + 관측정 수위 + 취수 기록 + 지질자료 → 모델 보정(역산) → 파라미터 앙상블 → 대리모델 → 강건 최적화 → 취수계획·불확실성·실행 불가 판정`

새 위성 관측이 들어오면 보정 단계부터 다시 실행해 파라미터 앙상블을 갱신한다.

## 2. 모듈 ① 위성 관측으로 지하 상태 추정

### InSAR 변형

- 입력: Sentinel-1 기반 변형 시계열. 공개 처리 결과가 있으면 우선 사용하고, 없으면 자체 처리한다.
- InSAR는 위성 시선 방향(LOS) 변위를 측정한다. 수직 변위로 쓰려면 상승·하강 궤도 결합 또는 수평 변위 무시 가정이 필요하며, 사용한 방법을 기록한다.
- 관측 기준점, 대기 오차, 결맞음 저하 구간을 품질 정보로 함께 보존한다.

### 역산(모델 보정)

- 추정 대상: 구역별 탄성·비탄성 저류계수, 수리전도도, 압축층 두께 관련 파라미터.
- 관측: 격자별 InSAR 변위 시계열, 관측정 수위.
- 방법: 목적함수(관측-모델 오차) 최소화로 시작하고, 불확실성은 앙상블 기반 방법(예: 앙상블 칼만 계열 또는 여러 초기값 보정)으로 파라미터 분포를 얻는다. 방법은 첫 2주 실험 후 확정한다.
- 출력: 파라미터 앙상블(N개 세트). 이후 모든 계산은 앙상블 전체에 대해 수행한다.

## 3. 모듈 ② 취수계획 변경 시 미래 계산

### 물리모델

- MODFLOW 6의 지하수 흐름과 CSUB(압축층 침하) 패키지를 사용하고, Python에서는 FloPy로 모델을 생성·실행한다.
- 초기 범위는 한 지역의 단순화된 층 구조다. 층 구성과 경계 조건은 [검증 지역 선정](REGION_SELECTION.md) 후 정한다.

### 대리모델

최적화는 물리모델을 수천 번 호출해야 하므로 대리모델을 둔다.

| 단계 | 방법 | 용도 |
|---|---|---|
| 기준 | 응답 행렬: 취수정별 단위 취수 변화에 대한 관리 지점 수위·침하 응답 | 선형 근사, 최적화 기준선 |
| 고도화 | 물리모델 실행 결과로 학습한 신경망 대리모델 | 비선형(비탄성 압축 개시 등) 반영 |

대리모델은 물리모델과 비교한 오차를 관리 지점별로 기록한다. 오차가 허용치를 넘는 영역에서는 최종 계획을 물리모델로 재검증한다.

## 4. 모듈 ③ 불확실성을 반영한 취수계획

- 결정 변수: 취수정별·기간별 취수량, 대체 용수 구매량.
- 목적: 취수 비용 + 대체 용수 비용 최소화.
- 제약: 수요 충족, 취수정 용량, 관리 지점의 수위 하한·침하 상한.
- 불확실성: 파라미터 앙상블의 각 시나리오에서 제약을 평가한다. 기본은 모든 시나리오 충족(강건 제약)이며, 허용 위반 확률을 두는 기회제약 방식을 비교 옵션으로 둔다.
- 실행 불가: 대체 용수 상한까지 써도 제약을 만족할 수 없으면 해를 만들지 않고 실행 불가와 원인이 된 제약을 반환한다.
- 풀이: 응답 행렬 기준에서는 선형계획(LP)으로 풀고, 신경망 대리모델에서는 비선형 최적화 또는 반복 선형화로 푼다.

## 5. 출력과 화면

| 화면 | 내용 |
|---|---|
| 입력 | 수요, 관리기준, 단가, 계획 기간 |
| 계획 | 취수정별 주간 취수량 표, 대체 용수량, 총비용 |
| 위험 | 관리 지점별 수위·침하 예측 범위(앙상블 분포) |
| 자료 부족 | 파라미터 불확실성이 큰 구역, 추가 계측 후보 |
| 비교 | 기존 계획 대비 비용·기준 초과 빈도 |

## 6. 기술 스택 후보

Python, FloPy·MODFLOW 6, NumPy·pandas·xarray, PyTorch(대리모델), SciPy 또는 Pyomo + 오픈소스 LP 솔버, Streamlit 또는 웹 프레임워크(팀 역량에 따라 결정). 버전은 개발 환경 구성 시 고정한다.
